# 代理工作流（Agent Workflow）

这份文档写给**用对话代理（Codex / Claude / ChatGPT 等）操作这套系统**的人，而不是写给人点界面的人。

核心原则只有一条：**代理走 MCP 工具，不走浏览器。** 浏览器自动化在这套系统上是错误路径——Cookie 与会话是按人隔离的，代理拿不到，也不应该拿到。

## 一、跨会话接入

- 部署后的管理站**不要**用云端浏览器去操作。浏览器 Cookie 与对话页面会话彼此隔离，不是受支持的自动化路径。
- 使用已安装的 Auto Ops MCP 工具。对外暴露的是 Streamable HTTP 端点 `/api/mcp`，鉴权为 OAuth 2.1 授权码 + PKCE（含动态客户端注册与刷新令牌轮换）。
- 当前对话里看不到这些工具时，请让用户在对话中启用已连接的 Auto Ops 插件——**不要在对话里索要 Cookie、OAuth 令牌、密码、邮箱验证码或站点绕过令牌**。
- 浏览器端管理界面使用「Sign in with ChatGPT」加服务端 owner 邮箱白名单。站点可访问 ≠ 数据接口公开，所有敏感接口都会校验 owner 身份。
- Sites 项目 ID 只用于源码/部署维护，不要把项目管理接口当日常运维 API 用。
- **任何情况下都不要打印、提交、落库或转发 Sites / OAuth 的 bearer token**；除非用户明确要求，不要轮换授权。
- 接入后先读 `GET /api/agent`，它返回当前可用的机器可读接口清单，比本文更权威。

## 二、安全上架七步

代理最容易出事的地方是「以为发上去了，其实图挂了」或「没确认就发布了」。按下面顺序走：

1. 通过站点授权头请求 `GET /api/health` 与 `GET /api/dashboard`，确认服务与店铺状态正常。
2. 用 `POST /api/xianyu/upload` 逐张上传图片（大图走分片：`begin_product_image_upload` → `upload_product_image_chunk` → `finish_product_image_upload`）。
3. 用 `POST /api/products` 创建**不发布的草稿**，请求体带 `"publishMode":"draft"`。
4. 用 `GET /api/dashboard` 把草稿读回来，逐项核对：标题、价格、原价、库存、运费、类目模式、发货模式、描述、**图片顺序**。这一步不能跳。
5. **没有当前对话里的明确确认，不要发布。** 不要用「用户之前说过要上架」来推断。
6. 用户确认后，调用 `PATCH /api/products`，请求体 `{"id": <草稿 id>, "action": "publish_listing"}`。
7. 用 `GET /api/xianyu/item?id=<item id>` 回读闲鱼侧商品，要求 `itemStatus` 为 `0`，并确认每一张图都能正常访问。

## 三、草稿与定时队列

草稿**故意不进** Cron 发布队列。已经在 `queued` 状态的记录仍按原定的定时发布行为执行——也就是说，把商品改成草稿不会取消一个已经排期的发布任务，需要显式处理。

## 四、失败时怎么处置

- 发货是「先发内容、再确认」两段式。第二段失败只能重试确认，不能重发内容——否则会重复发货。
- 单个任务失败会在订单台留下执行步骤记录，可以按步骤重试、重发或改用手动发货；不要直接改数据库绕过状态机。
- 缺配置、库存不足、订单失败、任务失败这四类告警是**幂等**的，同一问题不会重复轰炸邮箱，但也不代表问题已解决。

## 五、不要做的事

- 不要为了"跑通"而在代码里放宽 owner 校验或加匿名接口。
- 不要把真实 Cookie、卡密、上游 API 凭据写进日志、提交记录或对话。
- 不要在没有回读校验的情况下连续批量发布。
